# v14.6.9 構圖與 WebP 驗證

2026-11-11；本版沿用 v14.6.8 圖像內容，調整網頁呈現、格式與綠色粒子大小。

## 構圖

`scene-config.js` 以比例定義角色範圍：側臉背景為左側 84%，傳送門背景為左側 68%。`scene-framing.js` 保持圖片比例，將角色範圍放入可用空間；桌機與登入卡片至少保留 32px，寬度小於 1100px 則改成上圖下表單。背景空白區另以柔焦延伸，圖片邊緣淡入環境，沒有改寫原圖。

## 圖片輸出

- 網頁使用原尺寸 WebP：傳送門 1672×941／293,662 bytes；側臉 1920×1080／452,402 bytes。合計 746,064 bytes，比前版 3,559,977 bytes 減少約 79%。
- 4K 輸出為 3840×2160：使用系統 `sips` 重採樣，再以 Pillow 編碼 WebP（quality=92、method=6）。這是原圖放大，不是原生 4K，也沒有新增繪製細節。
- PNG 原圖、舊版圖片保留。`webp-exports.json` 記錄尺寸、大小與 SHA-256；網站不載入 4K 放大檔。

## 粒子

小粒子沿用 5–12px 基礎尺寸，每次重生有 28% 機率放大為 1.5–2 倍。維持綠色與既有粒子數量、閃電、不規則分岔及光暈，不加入火焰區塊。`?effects-test` 模式的 canvas 資料屬性提供當次 resize 的粒子樣本，供 DOM 核對。

## 驗證

- 230 項 Node 測試通過，包括 8 種視窗下兩張圖片等比例與角色範圍的計算。
- Brave 實際檢查 1662×1239、1440×900、1366×768、834×1112、390×844、320×568；兩張背景均載入，角色與表單不相交，沒有水平溢出或主控台錯誤。結果見 `responsive.json`。
- 320×568 以假資料確認登入 CMS、開啟管理員選單及登出返回 Login，見 `demo-session.json`；仍是前端示範登入。
- 報告中的座標是相對視窗，頁面捲動時可能為負值；相交判斷使用同一座標系。未宣稱實機 Safari／Firefox 驗證。
